### 5.1 顺序:图片 → 语音 → 音乐 → 视频

4. **超分区** —— 先清 0017–0020 的存量实例 → 打 `pool=sr` → 建 `seedvr2` 4×1 → **一台一台起,盯 `MemAvailable ≥15 G`**。

6. **视频区(最后)** —— 清 0034/0035/0039/0041–0043 评测容器 → H3 五个 Model **一台一台起,等 `/ready 200` 再下一台**(97–148 G 权重从 NFS 冷读,并发起会抢死带宽,见 60 卡实录 §3.5)。

> **删除一律"新副本 Running 之后再删旧的"**,别先删后建。
> **卡位由部署顺序决定**:调度器 `chosen = free[:need]` 按 GPU index 从小到大取前 N 张全空卡(`lightx2v_resource_fit_selector.py:154`),`placement_strategy` 默认 SPREAD(`schemas/models.py:237`)先摊到不同节点。所以同节点多模型时,**想占低位卡的先建**,且等上一个全 Running 再建下一个,否则串位。

### 5.2 custom backend 多副本只能 Auto,必须配 worker_selector

运维手册 §4.1a 坑 D:**vLLMOmni / ACEStep 这类 custom backend,Manual 选卡只支持单个 worker**;多副本跨机会报 `Manual GPU selection across multiple workers is not supported` → 只能用 **Auto**。

Auto 是"整卡独占 + 调度器自动填空卡",**不加约束会把实例撒到视频区的整机上,把整机咬碎**。所以先给 50 台 worker 打池标签:

```bash
# labels 是 merge 语义
curl -X PUT "http://10.0.0.238/v1/workers/<id>" -H "Authorization: Bearer $KEY" \
  -H 'Content-Type: application/json' -d '{"labels":{"pool":"image"}}'
```

池值:`image`(0001–0009)· `speech`(0010–0013)· `music`(**只打 0015/0016**,0014 待 music3)· `sr`(0017–0020)· `spare`(0021–0033)· `video`(0034–0050)。

**打标签的时机很重要**:池里空卡越多、Auto 的落点越不确定。规律是**先把池子卡到"刚好够"**,起完再把预留机纳入。语音区就是靠这招落成 0011–0013 各一份的。
模型的 **Worker Selector** 填对应 `pool=xxx`,调度器的 `label_matching_filter` 会把候选集限死在本池内,Auto 也咬不到别人的机器。**这一步是整个规划成立的前提。**
