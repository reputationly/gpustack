## 3. 恢复顺序(2026-08-26 起)

已完成:`z-image` 4 · `qwen-image-edit` 4 · `ace-step` 4 · `seedvr2` 4(拉权重中)。

| 批 | 模型 | replicas | 落点 |
|---:|---|---|---|
| 0 | **先用 z-image 发一单真实请求** | — | 验证 cu130 镜像能真出图(见 §0.1)——**这是整条恢复线唯一的质量门禁** |
| 1 | `qwen-image`、`ernie-image-turbo` | 4 + 4 | 0004–0007 的 GPU0 / GPU3 |
| 2 | `moss-voicegen`、`qwen3-tts`、`indextts-2` | 3 + 3 + 3 | 0011–0013 |
| 3 | `hunyuan-image-3` | 3 | 0001–0003 整机 |
| 4 | `minimax-h3-base-fl2va` → `fl2va` → `fast-fl2va` | 2 + 4 + 4 | 0021–0030 |
| 5 | `minimax-h3-base-ref2va` → `ref2va` → `fast-ref2va` | 2 + 4 + 4 | 0031–0040 |

**不要一次性把 replicas 全调回去**。50 台同时拉权重会同时打爆 NFS 和 GPU。
4/5 批是 H3,**一个模型一个模型放,每个等全副本 Running 再下一个**。

既有教训:ARM A100 上任何 4 路 offload 并发会整机死机。

## 5. 关键约束

### 5.1 卡位由 gpu_selector 决定,不要手工勾卡

库里每个模型都已 pin 死 `gpu_ids`。若要新建/改模型,注意调度器的两条机制:

- `chosen = free[:need]` —— 按 GPU index 从小到大取前 N 张**全空**的卡
  (`policies/candidate_selectors/lightx2v_resource_fit_selector.py:154`);
- `placement_strategy` 默认 **SPREAD**(`schemas/models.py:237`),先把副本摊到不同节点。

所以**同节点多模型时,想占低位卡的先建,且等上一个全 Running 再建下一个**,否则串位。

另注:vLLMOmni / ACEStep 是 custom backend,**Manual 选卡只支持单个 worker**,
多副本跨机只能 Auto(手册 §4.1a 坑 D)。用 `worker_selector` 锁池可防止 Auto 咬碎整机。

### 5.2 ⚠️ 11 个 replicas=0 的模型,pin 的是 wan2.2 时代旧坐标,会和在编模型撞车

| 模型 | pin 的节点 | 撞谁 |
|---|---|---|
| `wan2.2-t2v` | 0001 0002 | hunyuan-image-3 |
| `wan2.2-i2v` | 0003 0004 | hunyuan + 图片区 |
| `wan2.2-flf2v` | 0025 0027 0028 | h3-fl2va / fast-fl2va |
| `infinitetalk-480p` | 0005 0006 | 图片区 |
| `infinitetalk-720p` | 0007 0008 | 图片区 |
| `bernini` | 0009 0010 0014 0015 | ace-step(**引擎已下线,见 §0.1,不要再启用**) |
| `moss-ttsd` | 0016 0017 0023 | ace-step / seedvr2 / h3 |
| `ltx2-v2a` | 0016 0017 0023 | 同上 |
| `audiox` | 0010 0014 0023 | h3-fl2va |
| `soulx-singer` | 0018 0019 0020 | seedvr2 |
| `wan2.2-vace` | 0009 0010 | **不撞**(唯一一个) |

**谁顺手把这些 replicas 调上去,就会和在编模型抢卡。** 要启用其中某个,
先把 pin 改到空闲的 0008 / 0009 / 0010 / 0014,再调 replicas。

**`bernini` 例外:引擎镜像已随 `5f1697c8` 下线且卡在 cu128 base(py3.11 与 cu130 的 py3.12 冲突),
改 pin 也起不来** —— 要复活得先解决 Python 版本问题。

### 5.3 其余红线

- **单卡模型必须显式设 GPUs per Replica = 1**,否则 Manual 勾 N 卡会按 N÷副本 分卡,launcher 找不到变体直接失败(手册坑 17-8);
- **Enable Model Route 建时就勾**,建完改不了(60 卡实录 §3.3);
- **准入背压的两张表不落盘** —— `set_config` 只做 `setattr`(`routes/config.py:45`),
  **server 容器一重建就回到启动参数值**。升级流程收尾必须重新配一遍,或固化成启动参数。

## 6. 遗留

1. **驱动升级 0001–0050**(570.86.10 → 580.65.06)。cu130 已证明不需要它(`cu130-py312-upgrade` §1.1),
   现在的理由只是消除对 `cuda-compat` 的隐性依赖 + 统一基线,优先级可降。驱动是 runfile 装的,
   **关机重启不会升级**,须逐台跑 runfile。挡新实例落上去的抓手:把 worker 置 `MAINTENANCE`
   (`policies/worker_filters/status_filter.py:21` 只认 `READY`)。
2. **Turbo8 / ref2va 各档热态耗时**未实测,§4 是外推值,上线后回填并同步 Per-model Latency 表。
3. **Per-model Queue Wait 表**:后端字段 `lightx2v_model_queue_wait_seconds` 早已存在,
   前端表单 2026-08-23 才补(gpustack-ui `c5836b12`),**要等下一次出包才在 UI 可见**。
   在那之前只能 `PUT /v2/config`。不配的话按默认 image 25 s / video 150 s,
   hunyuan 第 4 个并发、H3 Turbo4 第 5 个任务就会被 429。
4. **机动池 0041–0050 怎么花**:默认备着给 H3 扩容;图片/语音侧有排队压力时可切几台过去。
