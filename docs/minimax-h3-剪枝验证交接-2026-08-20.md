## 0. 一句话背景

`multimodalart/MiniMax-H3-Pruned` 把 H3 的 AdaLN 调制投影做了秩分解(2688 维输入 → 8 维),
砍掉 39.3% 的 DiT 参数(13.03B),数值上**比官方 bf16 发布版更接近精确解**。
我们要回答两件事:**① 在我们的 offload 场景下它到底省多少;② 叠上 turbo LoRA 还成不成立。**
结论出来后再决定要不要改 vLLM-Omni 引擎去支持它。

## 2. 已完成的工作

### 2.1 昨天(08-19):新老镜像 / 模型档位 / 提示词写法 三轮对比

结果目录 `/nfs-output/h3_img_eval_20260819/`,看片入口 `compare/`(三组软链),
汇总表 `/nfs-output/h3_img_eval_20260819/SUMMARY.md`。三条已坐实的结论:

1. **老镜像的 8 步是假 8 步。** 逐步日志对齐:老镜像对 `num_inference_steps=8` 只做 7 次
   transformer 评估(step 0–6),新镜像做满 8 次;每步耗时两边都是 42s。根因是新镜像新增的
   `vllm_omni/diffusion/sched/sigma_schedule.py` 会读 checkpoint 里的蒸馏调度
   (`base_schedule` 9 个 sigma 边界 = 8 次评估)。
2. **线上实例 0001/0002 也是假 8 步。** 它们挂的是 `MiniMax-H3-FL2VA-Turbo8-BF16`(plain),
   那份 `model_index.json` 没有 `base_schedule`/`distilled` 块;要吃蒸馏调度得换成
   `-vLLM` 那份。turbo4 差别更大:plain 的 `flow_shift.video=12.0`,`-vLLM` 是 `6.0`。
3. **提示词必须按官方三字段规范写。** `[Shot N] + At 00:0X.XXX` 的切点会被严格执行 ——
   官方示例的唯一切点写在 4.500s,实测帧间差尖峰精确落在 4.50s;我们改写版写的
   3.00/6.00/9.00/11.50,base 20 步实测尖峰落在 3.00/6.00/9.00/11.38。
   规范在 `/nfs-models/wuhanjisuan894/models/MiniMax-H3/docs/VIDEO_PROMPT_WRITING_GUIDE_base_en.md`。
   官方可复现请求在 `/nfs-models/wuhanjisuan894/models/MiniMax-H3/scripts/readme/reproducible-768p-t2va-request.sh`
   (short_edge 768 / 16:9 / 10s / seed 0)。

> ⚠️ 当时用"平均亮度"推断过"色彩指令没被执行",**已被用户肉眼否定**,该指标不能用来判断色板。
> 同理,"base 高步数不值"这个结论也只有客观指标支撑、**未经肉眼确认**,属待验证。

```bash
ssh gpu40 'bash /nfs-output/h3_pruned_eval/run_one.sh <TAG> <MODEL_DIR> <NFE> [LORA_PATH] [VIDEO_SHIFT]'
```

## 6. 已经踩过的坑(别再踩)

1. **索引必须本地化。** 剪枝仓自带的 `modular_model_index.json` 把 text_encoder/scheduler 指向远端
   `MiniMaxAI/MiniMax-H3`,离线下报 `does not appear to have a file named scheduler_config.json`。
   已就地替换;`--index-name` 这个 kwarg 这版 diffusers **不支持**,别再用。
2. **peft 版本。** 镜像不带 peft;NFS 上遗留的 `peft-0.17.1` 与 transformers 5.14.1 不兼容
   (import 已删除的 `HybridCache`)。**用 0.19.0**,wheel 已缓存。
3. **`load_lora_adapter(prefix=None)` 仍然是错的。** PEFT 0.19 会创建 624 个参数壳,但源 key 已带
   `.lora_A.default.weight`,通用加载器又建立 `default_0`/重复 suffix,结果 624 张量一个都没装进去。
   仅看“注入 624 个参数”是假阳性。当前 harness 改为显式 `LoraConfig + add_adapter`,检查 A/B 配对、
   target、rank、alpha、key/shape 集合,再逐张量比对。正式 Turbo8/4 都是 624/624 exact、312 targets、
   rank 128;alpha 8/128,effective scale 0.0625/1.0。旧结果在 `invalid_no_lora_20260820_0710/`。
   (LoRA 不碰 AdaLN,结构上与剪枝不冲突,但质量仍须实测。)
4. **一台机器只能跑一发。** group offload 把权重压 CPU,一发约 133 GB / 251 GB。要并行就换节点。
5. **节点上还挂着评测引擎会占卡和内存。** `docker rm -f $(docker ps --format '{{.Names}}' | grep imgeval)`,
   重启用 `/nfs-output/h3_img_eval_20260819/launch_engine.sh`(约 7 分钟)。
6. **别同时开串行链和并行调度**,会撞车跑同名 tag、互相覆盖产物。串行链已全部停用。
7. **gpu31/32/33/34/36/37 上有别人的 `h3-opt03-*` / `h3-align01-*` 容器,不要动。**
8. **H3 scheduler 的参数是 sigma grid points,不是 NFE。** 传 8 只会 forward 7 次。当前 harness
   把请求 NFE 转成 NFE+1 grid points并用 pre-hook 硬断言;旧错步数结果在
   `invalid_wrong_schedule_20260820_0737/`。
9. **正式模型路径统一使用 `/nfs-models`。** `/nfs-data/models` 在当前集群只是同一 inode 的旧别名,
   但 `run_one.sh` 已不再挂载它,两个 modular index 也已改成 `/nfs-models`。旧索引备份为
   `modular_model_index.nfs-data-paths-20260820.bak`。

## 7. 后续计划(按优先级)

### P0 · 六发正式配对与报告 —— 已完成
三组配对、机器指标和软链目录均已生成。见 `SUMMARY.md` 和 `COMPARE_20260820/`。

### P1 · 质量判定(必须人眼)
只看正式目录中的 `official.mp4` vs `pruned-r8.mp4`,不要使用 `*_base_s20` 历史 19-NFE 结果。
上游给的参考:端到端扰动量与"换 attention 后端"同量级(视频 latent cosine 0.99128 vs 对照 0.99248)。
**客观指标(码率/亮度/运动)只能当辅助,不能替代肉眼** —— 昨天已经在"亮度"上栽过一次。

### P2 · 若质量过关:改 vLLM-Omni 支持剪枝权重
改动集中在 `vllm_omni/diffusion/models/minimax_h3/minimax_h3_transformer.py`(镜像内路径
`/usr/local/lib/python3.12/dist-packages/vllm_omni/...`),三处:

1. **AdaLN 宽度 —— 目前没有通,必须改。** 剪枝 config 同时保留 `time_embed_dim: 2688` 并新增
   `adaln_rank: 8`;当前 `MiniMaxH3DiTArchConfig` 不读取 `adaln_rank`,所以仍会建 2688 宽带 bias 投影。
   需要显式把低秩宽度接入 arch/config、block 和 norm-out 投影,并按是否存在剪枝张量选择实现。
2. **时间步嵌入 —— 要新写。** checkpoint 是 fp32 `[1025,8]` table + `[8,2688]` basis +
   `[2688]` mean,按 1025 项查表并线性插值。这个 table 已是激活后的曲线,剪枝分支**不能再做 SiLU**。
3. **投影无 bias,折叠偏置必须 fp32。** block weight 是 bf16 `[96768,8]`,另有 fp32
   `folded_bias [96768]`;norm-out 同样为 `[10752,8]` + fp32 folded_bias。加法/转换顺序要与上游一致,
   不能让 `params_dtype=_BF16_DTYPE` 静默吞掉调制量。

外加 diffusers 布局到 vLLM key 命名的映射。
**basis 不能自己解**:秩-8 子空间只在符号和旋转意义下唯一,必须沿用 checkpoint 里那份
`time_embedder.table`(上游实测自解的旋转会引入 1.10–1.63 的相对误差)。

### P3 · 可选
- **ref2va 验证**:`transformer_ref/` 已下好,把 `run_pruned_compare.py` 的 `workflow` 改成 `ref2va`。
- **turbo4 原生 768p 验证**:改 manifest 的 `width/height/num_frames`,这套 offload 下每发约 13 分钟。
- **int8 + ConvRot**:剪枝仓自带 `enable_convrot` / `quantize_8bit`(torchao),上游称可把 transformer
  压到 ~19.5 GB、cosine 0.9893(优于普通 int8 weight-only 的 0.9773)。**这条才是解显存的**。
- **长视频编排**:`Smite79/MiniMax-H3-Longvideos` 的做法(末帧接力串戏拍到 ~120s)可在 facade 层实现,
  我们已有 `l2va`/`flf2v` 任务类型。坑:每拍要重盖身份信息、非对白镜头要静音、名词短语会触发人物复制。
